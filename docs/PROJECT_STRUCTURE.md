# Project Structure — Android monorepo

Two build systems, one repo: **Gradle** owns the app (Kotlin), **npm** owns the data/tooling
(catalogue, i18n, eval-set compilation). The seam between them is exactly one file:
`android/core/src/main/assets/catalogue.json`.

## Placement rules

| Question | Answer |
|---|---|
| Where does a user-visible fact live? | `packages/catalogue/data/*.yaml` with citation. **Never in a Kotlin string.** |
| Where does matching/answering logic live? | `:core` (pure JVM). If it needs `android.*`, it is in the wrong module. |
| Where does mic/speaker code live? | `:voice` only. `:app` talks to an interface, so `:core` tests and Robolectric never need a mic. |
| Where does a judge-checkable number come from? | `results/`, produced by `tools/bench/*` or `scripts/bench-all.sh`. |
| Speech model weights? | `android/voice/src/main/assets/model/` at build time, gitignored, copied by `scripts/fetch-models.sh` (hash pinned in NOTICES.md). |
| Raw field recordings (contain voices = PII)? | Nowhere in git. Derived CSV + consent log only, in `results/field/`. |
| Generated assets (`catalogue.json`)? | **Committed.** A reviewer must be able to read exactly what the shipped APK contains. |

## Minimal viable demo (if everything after this slips, we still submit)

1. `:core` answers income-certificate questions in HI + EN from cited data.
2. `:app` renders J1 + J4 (refusal) with TalkBack-clean semantics.
3. APK installs on the budget phone, airplane mode, cold start < 2 s (J5).
4. Voice: V0 text + chips working, V1 Vosk ASR transcribing on-device (TTS may be eSpeak).
5. `results/stepcount/` + `results/qa/` + `results/refusal/` exist and are regenerable.
